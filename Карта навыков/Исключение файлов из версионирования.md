## Что нужно знать

`.gitignore` — текстовый файл со списком имён и шаблонов, которые Git должен игнорировать и не отслеживать. Он предотвращает попадание в репозиторий временных файлов, логов, секретных ключей и папок сборки, сохраняя проект чистым. Имя файла зарезервировано и пишется в точности так, с точкой в начале.

Файл понимает шаблоны, а не только имена. Строки `build/` достаточно, чтобы исключить папки `build` всех проектов репозитория разом — перечислять каждую не нужно.

Для разных языков и систем сборки существуют типовые наборы шаблонов: в них собраны кэши, папки сборки и временные файлы, свойственные конкретной технологии. Такой набор умеет генерировать, например, GitHub. В курсе используется сборка через `cmake` и `make` без лишних инструментов, поэтому хватает `.gitignore` из трёх строк — папка сборки `build/`, папка настроек редактора `.vscode/` и служебный файл Finder `.DS_Store`.

Исключаемое делится на три группы, и различать их полезно: **производное** — то, что порождают инструменты из исходников и восстанавливают в любой момент (`build/`); **личное** — настройки конкретного рабочего места, никому больше не нужные (`.vscode/`); **мусор операционной системы** — файлы, которые заводит не человек и не инструменты сборки, а сама система (`.DS_Store` в macOS, `Thumbs.db` и `desktop.ini` в Windows).

Мусор операционной системы удобнее исключить один раз для всех репозиториев — личным списком исключений, который живёт вне проектов:

``` bash
git config --global core.excludesfile ~/.gitignore_global
```

Имена шаблонов вписываются в `~/.gitignore_global`. В `.gitignore` проекта их всё равно оставляют: личный список есть только у вас, а репозиторий читают и другие.

## Как разобраться, почему файл не виден Git

Когда файл не появляется в списке изменений, вопрос обычно не «исключён ли он», а «каким именно правилом». Правил несколько, и живут они в разных местах: `.gitignore` в корне репозитория, `.gitignore` во вложенных папках, личный список из `core.excludesfile`, файл `.git/info/exclude`. Угадывать не нужно — Git называет сработавшее правило сам:

``` bash
git check-ignore -v .DS_Store
```

``` 
/Users/ivan/.gitignore_global:1:.DS_Store	.DS_Store
```

Ответ читается как «файл, двоеточие, номер строки, само правило»: `.DS_Store` исключён первой строкой личного списка. Если бы сработал `.gitignore` репозитория, в начале стояло бы его имя. Пустой ответ означает, что файл не исключён ничем и его невидимость вызвана другой причиной.

Обратная ситуация — файл исключён, но всё равно попадает в коммиты. Это значит, что он был добавлен под контроль версий раньше, чем появилась строка в `.gitignore`: правила действуют только на неотслеживаемые файлы. Убрать из-под контроля, оставив на диске, — `git rm --cached имя_файла`.
