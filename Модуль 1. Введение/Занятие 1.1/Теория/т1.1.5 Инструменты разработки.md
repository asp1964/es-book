## От исходного текста к машинным командам

Процессор выполняет инструкции из фиксированного набора — это входило в его определение во втором разделе занятия. Программа на языке **C** — обычный текстовый файл; ни одна его строка инструкцией процессора не является. Перевод текста программы в машинные инструкции выполняет компилятор.

![[Компилятор#^def]]

В определении существенны последние слова: *для конкретной аппаратной платформы*. Наборы инструкций у разных процессоров разные, поэтому результат компиляции привязан к архитектуре: программа, скомпилированная для процессора x86 персонального компьютера, не может исполняться на ядре ARM Cortex-M — и наоборот. Стандартным компилятором языка **C** является GCC (GNU Compiler Collection) — свободный компилятор, существующий в вариантах для десятков архитектур.

## Кросс-компиляция

При разработке для персонального компьютера программа компилируется и выполняется на одном и том же процессоре. С микроконтроллером так не получится: как показано в третьем разделе, у него нет ни операционной системы, ни памяти, ни средств ввода для запуска компилятора. Возникает разделение, уже знакомое по описанию рабочего места разработчика: компиляция происходит на [[Целевое устройство#^def|хосте]] с процессором x86, а выполняться программа будет на целевом устройстве с ядром ARM Cortex-M0+.

![[Кросс-компиляция#^def]]

Для микроконтроллеров с ядрами ARM Cortex-M используется кросс-компилятор `arm-none-eabi-gcc` — тот же GCC, но порождающий инструкции ARM. Его название читается как паспорт целевой платформы: `arm` — архитектура целевого процессора; `none` — на целевом устройстве нет операционной системы; `eabi` (*embedded application binary interface*) — соглашение о формате двоичных файлов и вызовах функций для встраиваемых систем.

## От машинных команд к файлу прошивки

Результат работы компилятора — объектный файл (расширение `.o`): машинные инструкции, у которых ещё не зафиксированы адреса размещения в памяти. Проект обычно состоит из нескольких исходных файлов и библиотек, и каждый компилируется в свой объектный файл. Объединяет их компоновщик (*англ. linker*): он связывает обращения между файлами и раскладывает код и данные по адресам постоянной и оперативной памяти микроконтроллера. Какие области памяти существуют и где начинается каждая — компоновщику сообщает отдельный текстовый файл, скрипт компоновщика; в практической части он копируется в проект из SDK готовым.

Итог компоновки — исполняемый файл `.elf`. Последний шаг — преобразование его в формат UF2: именно такой файл понимает встроенный загрузчик платы Pico. Весь путь выглядит так:

```text
main.c        исходный текст на C
  │
  │  компилятор (arm-none-eabi-gcc)
  ↓
main.o        объектный файл: машинные инструкции без адресов
  │
  │  компоновщик (arm-none-eabi-ld)
  ↓
blink.elf     исполняемый файл: код и данные размещены по адресам
  │
  │  преобразование формата
  ↓
blink.uf2     файл прошивки для загрузки на плату
```

Компилятор, компоновщик и вспомогательные утилиты распространяются и работают вместе, последовательно передавая друг другу результат.

![[Набор инструментов компиляции#^def]]

Устанавливая `arm-none-eabi-gcc`, разработчик получает весь набор: компилятор, ассемблер, компоновщик и утилиты для работы с готовыми файлами.

## SDK: готовые компоненты производителя

Набор инструментов переводит исходный код в прошивку, но не отвечает на вопрос, откуда этот код взять. Даже для мигания светодиодом собственного `main.c` недостаточно: перед вызовом `main()` микроконтроллер должен быть подготовлен к работе — настроено тактирование, инициализирована память. Писать этот код самостоятельно для первого проекта означало бы начать с самого сложного. Производители решают задачу поставкой SDK.

![[SDK (Набор инструментов разработки)#^def]]

Для RP2040 производитель поставляет pico-sdk. В него входят стартовый код, выполняющийся до `main()`, функции работы с периферией, описание сборки, примеры проектов и документация. Благодаря функциям SDK первая программа записывается в несколько строк:

```c
gpio_init(PICO_DEFAULT_LED_PIN);              // инициализация вывода
gpio_set_dir(PICO_DEFAULT_LED_PIN, GPIO_OUT); // вывод работает на выход
gpio_put(PICO_DEFAULT_LED_PIN, 1);            // включить светодиод
sleep_ms(500);                                // задержка 500 мс
```

Распространяется pico-sdk как Git-репозиторий — здесь происходит первая практическая встреча с системой контроля версий, о которой шла речь в предыдущем разделе: SDK не скачивается архивом, а клонируется командой `git clone`. Путь к склонированной копии записывается в переменную среды `PICO_SDK_PATH` — по ней инструменты сборки находят SDK на диске.

## Система сборки

Проект — это собственные файлы разработчика плюс десятки файлов SDK. Каждый нужно скомпилировать с правильными параметрами, а затем скомпоновать в правильном порядке. Вызывать инструменты вручную для каждого файла возможно, но трудоёмко и чревато ошибками. Эту работу автоматизирует система сборки.

![[Система сборки#^def]]

В курсе, как и в pico-sdk, используется связка двух инструментов, работающих в два этапа.

1. **Конфигурация.** CMake читает описание проекта — файл `CMakeLists.txt`, в котором перечислены исходные файлы и используемые библиотеки SDK, — и порождает сценарий сборки. Этап выполняется командой `cmake` и повторяется только при изменении состава проекта.
2. **Сборка.** Make исполняет порождённый сценарий: вызывает компилятор и компоновщик для каждого файла. Этап выполняется командой `make` и повторяется после каждого изменения кода, причём перекомпилируются только изменённые файлы.

Обе команды встретятся в практической части в точности в этом порядке: сначала `cmake` в новой директории `build`, затем `make` после каждой правки кода.

## Загрузка прошивки

Файл `blink.uf2` получен и лежит на диске хоста. Остался последний шаг — записать его в постоянную память микроконтроллера. Традиционно для этого служит [[Программатор#^def|программатор]] — отдельное устройство между компьютером и микроконтроллером. Платформа курса выбиралась в том числе за возможность обойтись без него: в постоянную память RP2040 на заводе записан USB-[[Загрузчик#^def|загрузчик]]. Если удерживать кнопку BOOTSEL при подключении платы к компьютеру, загрузчик представит плату как USB-накопитель; копирование файла `.uf2` на этот накопитель и есть запись прошивки — после неё микроконтроллер перезапускается и начинает исполнять программу.

Для работы с прошивками из командной строки служит утилита picotool: она показывает сведения о собранном файле и о подключённой плате и умеет загружать прошивку без копирования вручную.

## Рабочее место и порядок действий

Остался инструмент, с которого работа фактически начинается, — редактор кода. В курсе используется Visual Studio Code, однако принципиальной роли выбор редактора не играет: все инструменты пути — компилятор, CMake, Make, picotool — вызываются из командной строки, и редактор нужен лишь для удобного набора текста программ и встроенного терминала. Специальная среда разработки, скрывающая эти вызовы за кнопкой «собрать», в курсе сознательно не применяется: на каждом шаге должно быть видно, какой инструмент работает и что он делает.

>[!info] Терминал берём системный, а не встроенный в редактор
>В VS Code есть собственный терминал, и работать можно в нём. В курсе мы намеренно пользуемся системным — PowerShell в Windows, zsh или bash в macOS и Linux. Причина в том, что сборка прошивки не является свойством редактора: её выполняют несколько отдельных программ, согласованно передающих друг другу результат. Когда команды набираются в системном терминале, видно, что CMake, Make, компилятор и picotool работают сами по себе, а редактор — лишь одно из мест, откуда их удобно запускать.

Полный порядок действий при создании проекта теперь можно записать вместе с инструментами каждого шага.

| Шаг                      | Инструмент               | Команда            |
| ------------------------ | ------------------------ | ------------------ |
| Получение SDK            | Git                      | `git clone`        |
| Написание исходного кода | Visual Studio Code       | —                  |
| Конфигурация сборки      | CMake                    | `cmake`            |
| Сборка прошивки          | Make + arm-none-eabi-gcc | `make`             |
| Загрузка на плату        | USB-загрузчик, picotool  | копирование `.uf2` |

Этот путь предстоит пройти вручную в практической части занятия: установить перечисленные инструменты, склонировать pico-sdk, создать проект `blink`, собрать его и запустить на плате. Каждая команда из таблицы будет выполнена в терминале, а результат каждого шага можно будет увидеть в виде конкретного файла — вплоть до последнего, мигающего светодиода.
